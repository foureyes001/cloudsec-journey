SECTION 8 : ELB & ASG

load balancer - distributes traffic among the servers 
	uses of LB (which are easy to  forget)-
	expose single point of access (DNS)
	provide ssl termination for  websites 
	enforce sstickiness through cookies
	separate public from private traffic

ELB - managed by aws and only config is responsibility of consumer

	provides health checks 
ALB,NLB,GWLB

ALB -load balancing multiple http apps across machines or same machine in different containers .supports websocket and http v2
	has port mapping feature to redirect to a dynamic port in ECS
	only has the feature of static dns hostname but not static ip

	Target groups - 
	can be ec2 instances  or ecs tasks or lambda functions all can be reached through http 
	or ip address of a server which is private 

	does health checks at target group level and ALB can route to multiple target groups


NLB (network load balancer) - layer 4                              [A]
	handles tcp, udp, tls - NOT http-aware, cannot read the request
	extreme performance - millions of req/sec with ultra low latency
	★ ONE STATIC IP PER AZ + can attach an elastic ip
	  -> this is the exam trigger. "needs a static ip" = NLB, every time
	target groups -
		ec2 instances
		ip addresses (private only)
		★ an ALB - you can front an alb with an nlb
		  -> gets you static ip AND layer 7 routing together
	health checks - tcp, http, https (3 protocols, more than layer 4 suggests)
	preserves client ip natively when targeting by instance id
	NOT in the free tier (alb and clb are)
	use when - tcp/udp traffic, extreme perf, static ip requirement

GWLB (gateway load balancer) - layer 3, works on ip packets        [A]
	purpose - deploy / scale / manage a fleet of THIRD PARTY network
	  virtual appliances: firewalls, ids/ips, deep packet inspection
	★ two functions in one box -
		transparent network gateway - single entry+exit for all vpc traffic
		load balancer - spreads that traffic across the appliance fleet
	★ GENEVE protocol, port 6081 - remember the number, it gets asked
	traffic path -
		route table -> gwlb endpoint (vpce) -> gwlb -> appliance fleet
		  -> back -> real destination
		traffic is inspected before it ever reaches your app
	target groups - ec2 instances, ip addresses (private)
	use when - question says "inspect all traffic" / "third party firewall"
	  / "ids or ips appliance"

★ pick-by-keyword - this is the actual exam skill                  [A]
	http/https/websocket/grpc, path or host routing   -> ALB
	tcp/udp, static ip, extreme performance           -> NLB
	traffic inspection, 3rd party appliance, geneve   -> GWLB
	anything described as legacy                      -> CLB
	

Sticky sessions - to log in to the same instance behind the LB thus eliminating the need of credentials everytime or no loss of session data  ...sticky-> cookies basically
	two types of app based cookie - custom and application cookie
	duration based cookie- expire in specific duration


CROSS ZONE LB - default enabled and no charge- ALB  
	   default not enabled and charge- NLB


TLS CERTIFICATES IN LB- 
	manage certs-> ACM
	https lister :
 		needs a default cert
		add optional certs for multiple domains which can use SNI to access the cert for the specific domain 

SNI - load multiple certs onto one server and based on hostname provide the cert for that domain when asked through the hostname . works for ALB,NLB and CloudFront


CONNECTION DRAINING- When a instance der registers or is unhealthy ,new requests are stopped and the completion of already provided requests in execution before stopping is connection draining. set the time alotted for draining as well from 1s to 1 hr
	
ASG SCALING POLICIES- 
	dynamic scaling- 
		target tracking scaling- eg :to keep avg usage around 40 percent
		step scaling - eg- scale up when CPU utilisation is above 60 and down when below 20
	scheduled - increase desired capacity by 2 from 3 to 5 pm everyday
	predictive -continuously forecast load and schedule it based on that

	SCALING COOLDOWNS - cooldown after scaling happens
